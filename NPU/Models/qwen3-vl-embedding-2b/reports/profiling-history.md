# 稳定单遍版并发 Profiling · 历史诊断

单卡 910B1、64 路输入，分别采集两组各 64 条。以下为图优化前的稳定 eager 版本，不能当作 SPG 的实测耗时分解。

| 项目 | screen | holdout |
|---|---:|---:|
| 无原生 Profiler：采集前 / 后中位耗时 | 8.471 / 8.383 s | 9.675 / 9.642 s |
| 预解码后 MM＋引擎重算 | 7.803 s | 8.098 s |
| 仅引擎重算诊断 | 7.762 s | 7.935 s |
| MM 工作累计 / 并集 | 5.397 s | 5.750 s |
| MM 队列等待 P50 / P95 | 0.609 / 1.364 s | 1.045 / 1.951 s |
| 原生 Profiler 窗口 | 9.924 s | 10.866 s |
| kernel 时间并集 / 窗口占比 | 3.359 s / 33.8% | 3.646 s / 33.6% |
| 有引擎请求而无 kernel 的窗口 | 5.886 s | 5.555 s |

原生 Profiler 引入约 12–17% 开销；kernel 时间覆盖率不是芯片理论算力利用率。
空隙包含 Host 提交、队列、拷贝、同步和采样影响，不能全部归因 Python。MM、解码与设备工作重叠，各列不可相加。
预解码与仅引擎实验改变了调度/缓存边界，只用于诊断，不作为生产端到端性能。

每组 105,600 条 kernel 记录：Cast 25,536、Mul 11,136、Add 10,880、ReduceMean 与 Rsqrt 各 3,648（57×64）。
设备算子时间中 MatMul 与 FusedInferAttentionScore 约占 62–63%，分母不是端到端耗时。
这些证据支持后续验证图执行与 Norm 融合；实际候选收益见 [优化记录](optimization-history.md)。

**affinity 解释修正**：当时记录的初始化快照不能代表稳态。后续核对发现引擎初始化后已经自动本地绑定，因此原“全核游走”推测和早期 +4.45% 绑核收益均撤回。正式优化对照保留了原生每线程绑定。
稳定版 Profiling 保存向量与原 NPU 字节一致；这一结论不延伸到 SPG，后者有新增数值差异。
